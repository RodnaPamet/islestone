## Summary

- **What moves.** The task engine's behaviour, renamed to the ADR 0006 vocabulary. That covers: the per-scope key counter, the pure transition check with discriminated errors and display-name refusals, create/list/get/update/delete/restore, assign, the four bulk verbs, comments, watchers and their bell fan-out, the assignment email and bell, the due-date reminder (shared helper plus daily job), the activity feed read from the audit trail, the post-commit side-effect order (audit, commit, automation, cache bump, watchers), and the tenant-scoping fixes: unlink scoped to the owning item, child writes check the parent is in the tenant, members must be ACTIVE.
- **What is cut.** Everything compliance-shaped:
  - `controlId`, `findingId`, `Evidence.taskId`, `remediatedVulnerabilities`, `templateTaskId`, `retentionUntil`;
  - the `TaskType`/`TaskSeverity`/`TaskSource`/`TaskPhase`/`TaskLinkEntityType` enums;
  - polymorphic `TaskLink` targets, the type-relevance gate, source reconciliation (`task-source-reconcile.ts`), SLA by severity;
  - the four-eyes reviewer (`reviewerUserId`, `IN_REVIEW`, reviewer eligibility, `TASK_REVIEW_REQUESTED`);
  - the mandatory `resolution` text, checklists in JSON, `metadataJson`, the evidence tab/routes, `listTasksByControl`, the legacy `/api/tasks` route and the `Issue*` aliases.
- **What is missing and must be written fresh for 2.1:** `Team`; `Project` (with key prefix and prefix history); `ProjectKeySequence` (per project, not per tenant); `WorkItemType` rows; `WorkflowState` rows per team in five categories; fractional `sortKey`; sub-items through `parentId`; `WorkItemRelation` (BLOCKS/RELATES/DUPLICATES) with cycle refusal under an advisory lock, plus a property test; `Label`/`WorkItemLabel`; `WorkItemLink` (URL/PR/commit/page/canvas).
- **What is missing for 2.2:** the `version` column with `If-Match` and 409; subtree soft delete with `deletionId`; comment edit/delete; and explicit `deletedAt` filtering (no extension).
- **Size.**
  - In scope at source: about 6,140 lines (16 modules plus 19 routes).
  - Carried forward after edits: about 3,900 lines.
  - Cut: about 2,800 lines.
  - New non-test code for the missing 2.1/2.2 pieces: roughly 3,000 lines. Fresh migration SQL: about 600 lines.
- **Blocker before any COPY row runs.** The task text says the owner has authorised copying, but nothing in Islestone records it yet:
  - ADR 0001 is unsigned, and its interim rule (lines 249–258) forbids copying.
  - Islestone `CLAUDE.md` ("Provenance and licences") forbids copying.
  - ADR 0002 says "pattern only, no code copied" (line 491).
  - Before step 1 of the order below, D1 must be signed and its reference recorded, and `CLAUDE.md` and ADR 0002 amended.

**Known traps:**

1. **Licence and process.** See the blocker in the summary. Every copied file must also "conspicuously display" BUSL-1.1 (ADR 0001, BUSL lines 65–66) unless the signed grant says otherwise. Decide the file-header form once, before step 1.
2. **Hard deletes in disguise.** `deleteTask` calls `db.task.delete` (task.ts line 746) and `bulkDeleteTask` calls `db.task.deleteMany` (line 694). Both are soft deletes only because `src/lib/soft-delete.ts` rewrites them for models in `SOFT_DELETE_MODELS`. Ported without that extension, they become **hard deletes**, cascading comments, links and watchers. Write explicit `updateMany` soft deletes. Add a test that a delete leaves the row with `deletedAt` set. Add a guard that `WorkItem` is never added to an extension model list, so the two mechanisms never stack.
3. **Nested soft-delete reads.** Prisma relation reads and `_count` ignore `deletedAt` (source `TaskRepository.ts` 597–605, #5305). Every nested read of sub-items, relations and comments filters `deletedAt: null` explicitly.
4. **Encrypted text leaking into the audit log.** `updateTask` logs `metadata: patch` (task.ts line 613), which carries the plaintext `description` into an audit row that streams to a SIEM in the source. ADR 0002 §11 requires "changed, not its text". Log field names only.
5. **Cursor shape.** The source cursor is `(createdAt, id)` desc; the list orders by `sortKey`. Reusing `buildCursorWhere` with a `sortKey` orderBy silently skips or repeats rows across pages.
6. **Date-only due dates.** `daysUntilDue` passes `dueAt` through `Intl` in `NOTIFICATIONS_TZ`. A `@db.Date` reads back as UTC midnight, which in any zone west of UTC formats as the *previous* day. That shifts every window by one and breaks the "overdue" filter. Compute the due day from the UTC date parts; convert only "now" to the zone.
7. **Job and RLS.** The source job reads every tenant through the global client (owner role, `superuser_bypass`) and writes `Notification` rows with no tenant context. No RLS applies and there is no auto-audit (source `docs/implementation-notes/2026-08-21-job-rls-tenant-context.md`). In Islestone, loop tenants and scan each inside the tenant context, or the job reads zero rows when the worker connects as `app_user`. The per-tenant loop also lets `[tenantId, stateCategory, dueDate]` serve the scan; the source's system-wide predicate has no `tenantId`.
8. **Relation direction.** `BLOCKED_BY` in the source is stored on the blocked side. Importers (5.5) and any copied test fixtures must invert it to `BLOCKS from=blocker`.
9. **Hard-coded model lists** that must change in the same PR as the models:
   - `SOFT_DELETE_MODELS` (`src/lib/soft-delete.ts`) and `SOFT_DELETE_TARGETS` (`src/lib/security/classification.ts` 243);
   - `ENCRYPTED_FIELDS` (`encrypted-fields.ts` 291–295);
   - `RESET_TABLES` (`tests/helpers/db.ts` 1120);
   - `RICH_TEXT_COVERAGE`, `LIST_QUERY_INDEXES`, the forward-lock list;
   - the retention inventory;
   - `route-permissions.ts` rules;
   - `CacheableEntity` (`list-cache.ts` 70) and `AggregationEntity`/`AGGREGATIONS['tasks-metrics']` (`aggregation-registry.ts` 35, 88–92), if the cache is ever ported;
   - `AssignmentNotificationKind`;
   - `NotificationType`/`EmailNotificationType`;
   - `JobPayloadMap`/retry options in `jobs/types.ts`;
   - `restore-validators.ts`, if anyone ports it.
10. **Editing another sub-phase's schema file.** Prisma needs both sides of every relation, so 2.1 must add relation fields to `Tenant`, `User` and `TenantMembership` in 1.3's `auth.prisma`. Use named relations from the start (`"WorkItemAssignee"`, `"WorkItemCreator"`, `"CommentAuthor"`) to avoid ambiguity errors.
11. **SQL Prisma cannot express.** Collation, DEFERRABLE, CHECKs, partial uniques. `prisma migrate dev` will not reproduce them and may propose dropping a partial index it does not know. Gate with a fresh-DB drift check and an expected-residue file, as the source does, plus catalogue tests.
12. **Enum values and rollouts.** Adding `WORK_ITEM_*` to 1.6's `NotificationType` after 1.6 has shipped is an `ALTER TYPE … ADD VALUE`. Before launch it is harmless. After any production deploy it is the two-deploy change ADR 0002 §3 describes: readers first, writer second. Prefer 1.6 reserving the values.
13. **Composite FKs need composite uniques on the target.** Prisma refuses a relation whose `references` is not unique. Declare `@@unique([id, teamId, tenantId])` on Project and `@@unique([id, teamId, category, tenantId])` on WorkflowState before the WorkItem relations. Moving an item between teams must write `teamId`, `stateId` and `stateCategory` in one UPDATE.
14. **Lock order.** Take `lockWorkItemGraph` FIRST in the transaction, before any row read or lock, or a relation write and a re-parent can deadlock. Large imports must batch graph writes, because the lock serialises the workspace.
15. **Generated-type churn.** Any Phase 1 port that quietly kept a `Task` reference stops compiling once `TaskStatus` and friends are gone: a copied `deadline-monitor.ts`, the dashboard repository, `work-tools.ts`. Grep the Islestone tree for `Task`/`task.` before step 1. ADR 0006's banned-identifier rule should land with this sub-phase.
16. **Circular imports.**
    - `task.ts` re-exports from `task-checklist.ts`, which imports `TaskRepository`; that cycle goes with the checklist.
    - Keep the due helper in `notifications/`, never `jobs/`: the usecase and the job both import it, and a usecase importing `jobs/` drags the job graph into the request path (source rationale in `task-due.ts` lines 11–17).
    - The automation stub must not import `jobs/`.
    - `domain/workflow-state.ts` must stay free of `@/lib/errors/types`, which imports `@/env`, so a client component can import it (Islestone's `client-env-boundary` guard).
17. **`errors/types` pulls `@/env`.** Any script or seeder that imports a usecase validates the whole server env (source `task-checklist.ts` 39–44). Keep seeders on repositories plus pure modules.
18. **`ctx.tenantSlug` optional.** Every bell helper returns early when `ctx.tenantSlug` is unset: `if (!ctx.tenantSlug) return` in `emitTaskDueNotification`, `emitTaskAssignedNotifications` and `emitTaskWatcherActivityBatch`. A context builder that omits it silences all notifications with no error. Assert it in the two-tenant test.
19. **Scale.** The source live list reads up to 5,000 rows uncursored. H2 seeds 100,000 items per tenant. Cursor-only from day one, and the Deleted view keeps its cap.
20. **Key search.** The source `q` matches `key contains`, a stored string. Islestone stores a number. Parse `ISL-123` (current prefix, prefix history, alias) for an exact hit, and keep title search separate; full-text is 2.7.
21. **Branding.** The email template's "Inflect Compliance" sign-off (`templates.ts` 106) and every `/tasks` link must not survive. A page or mail carrying the parent product's name is both a vocabulary breach and a brand problem.
22. **Optimistic concurrency.** The source `update`/`setStatus`/`assign` repositories read and then `update({ where: { id } })`, which is last-writer-wins. The version check must be the WHERE of one `updateMany`, with `count === 0` re-read to tell a 404 from a 409. A read-then-update leaves a race. `sortKey` writes do not bump `version` (ADR 0002 §5).
23. **Vocabulary leaks in prose.** Comments, refusal messages and audit `details` strings in the copied files say "task" and name TP-2, SOC 2, auditors, controls and findings throughout. ADR 0006 rule 4 ("prose follows code") makes each one a defect. Sweep every copied file before review.
