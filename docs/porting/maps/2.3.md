## Summary

- **What moves.** The tasks list client (filters, KPI strip, bulk bar with optimistic rollback, Deleted view with restore, quick-view side panel, column gear), the full-page detail (state picker, assignee, watchers, links, comments, activity, delete with undo, prev/next stepper), the create modal and its form hook, the autosave edit panel, the embedded "linked items" table (becomes the sub-items table), the panel tabs and activity feed, and the client data layer they stand on (`useTenantSWR`, `useTenantMutation`, `useEntityListIds`, `useGuardedPush`, `api-client`, `api-error`, `url-sync`, `CACHE_KEYS`). All renamed to ADR 0006: `Task` → `WorkItem`, status → workflow state, checklist → sub-items.
- **What is cut.** Severity, task type enum, source/provenance, the four-eyes reviewer and "Awaiting my review", the resolution prompt, template checklist and guidance, the Evidence tab and upload box, control/finding/vulnerability back-links, links to compliance entities (`EntityPicker`), linked vendors, KPI sparklines from the compliance snapshot, the SSR Redis payload cache, the `/tasks/dashboard` shim. About 2,350 source lines are not copied at all; most seed files lose a third to a half of their lines.
- **No kanban board exists in the source.** No board, swimlane, column drag or keyboard reorder (searched for `kanban`, `draggable`, `onDragStart`; the only drag code is the column-gear's mouse-only reorder in `checklist-gear-button.tsx`, the dashboard grid, and tldraw canvases). The board is new code on `@atlaskit/pragmatic-drag-and-drop`. It reuses: `useTenantSWR`/`useTenantMutation` (optimistic with rollback), the filter system and `FilterToolbar`, `AsidePanel` plus the edit panel as the card quick view, `useToastWithUndo`, `VirtualizedList` (react-window), `StatusBadge`, `InitialsAvatar`, `UserCombobox`, `TimestampTooltip`, `ToggleGroup`/`useViewMode` for the layout switch, `useKeyboardShortcut` (1.7), `usePublishDisplayedOrder`, and 2.1's pure `keyBetween`.
- **Size.**
  - In scope at source: about 10,600 lines (tasks route 4,908; three task components 1,029; panel helpers 281; undo hook and toast 406; client data libs 2,076; primitives no earlier map brings, plus the assignable-members route, 1,918).
  - Carried after edits: about 7,500 lines (about 5,700 of views and data libs, about 1,800 of primitives copied nearly as-is).
  - New code: board about 1,400 lines, shared detail body and relations/labels/sub-items about 600, versioned PATCH and cache helpers about 250, work-item picker about 150, project page about 80. Roughly 2,500 new lines.
  - Tests: about 3,700 source lines of rendered tests COPY+EDIT, about 2,700 of client-infra tests, about 1,500 of guards, one 360-line e2e spec, plus a fresh board e2e spec.
- **No Prisma models or migrations.** 2.3 reads what 2.1 and 2.2 create. One API addition is needed for the board (a combined move route), and possibly list indexes if the list offers sorts beyond ADR 0002 §13.

## Prisma models and migrations

- **No models, enums, RLS policies, triggers or migrations are created in 2.3.** Islestone starts a fresh migration history; no source migration is relevant. RLS for every table read here is created with the table in 1.3/1.6/2.1/2.2.
- **Models read** (through 2.2's API, never from a client), with the compliance parts already dropped by 2.1/2.2:
  - `WorkItem`: `id`, `projectId`, `teamId`, `number`, `typeId`, `title`, `description` (encrypted), `stateId`, `stateCategory`, `priority`, `assigneeId`, `creatorId`, `parentId`, `sortKey`, `dueDate`, `version`, `deletedAt`, `deletedByUserId`. Source `Task` columns that must not reappear in any view: `type`, `severity`, `source`, `key` string, `resolution`, `reviewerUserId`, `controlId`, `findingId`, `metadataJson`, `checklistJson`, `retentionUntil`.
  - `WorkflowState` (board columns, ordered by `position`; `isDefault` per category for checkbox ticks and category drops), `WorkItemType`, `Project` (`keyPrefix`), `Team`, `Label` + `WorkItemLabel`, `WorkItemRelation`, `WorkItemLink`, `Comment`, `WorkItemWatcher`, `AuditLog` (activity), `TenantMembership`/`User` (pickers).
- **Indexes the views depend on** (ADR 0002 §13, created by 2.1): project manual order `[tenantId, projectId, sortKey, id]`; board columns `[tenantId, projectId, stateId, sortKey]`; sub-items `[tenantId, parentId, sortKey]`; recently changed `[tenantId, projectId, updatedAt, id]`; filter by type `[tenantId, typeId]`; labels `[tenantId, labelId, workItemId]`. **If 2.3 offers more list sorts** (due date, priority, title, assignee), each needs a keyset order in 2.2's pagination helper and a backing index, which is a migration and a Layer C entry in the ported index guardrail. Recommendation: ship 2.3 with manual order and "recently updated" only; add sorts with 2.4's saved views.
- **Nothing per view is stored.** Column visibility, filter-card order, layout and lane choice are per-viewer `localStorage` (`ui-storage`) until 2.4's `SavedView`. Board order is the item's single `sortKey` (ADR 0002 §5); a per-view order would be a new table (ADR 0002 "What would change this decision").

## Ordering and risks

**Order** (each step typechecks on its own):

0. **Preconditions.** 0.1 grant recorded (and Islestone `CLAUDE.md` amended); ADR 0005 OQ4 decided; 1.2 including its required MIXED files and the optional rows named under "Import closure"; 1.4 (`PermissionSet.workItems`, `Role`, members route, `session-expiry`); 1.6 (`client-telemetry`); 1.7 (shell, `EntityListPage`, `EntityDetailLayout`, `FilterToolbar`, provider, `ui-storage`, `form-telemetry`, `use-dropped-link-click-guard`, catalogue); 2.1 (`workflow-state.ts`, `fractional-index.ts`, `work-item-key.ts`, states/types/labels routes); 2.2 (list, detail, metrics, bulk, restore, comments, watchers, links, relations, activity routes; `list-backfill-cap`; `workItemPath`).
1. **Client data leaves:** `api-error`, `api-client`, `url-sync`, `owner-display`, `swr-keys`, then `use-tenant-swr`, `use-tenant-mutation`, `use-entity-list-ids`, `use-guarded-push`, with their tests. Then the primitives handed to 2.3: `TruncationBanner`, `table-title-cell`, `mini-area-chart` + `kpi-accent` → `kpi-filter-card`, `bulk-action-bar`, `aside-panel`, the assignable-members usecase and route → `user-combobox`.
2. **Presentation helpers:** `workflow-state-badge`, `work-item-priority`, `work-item-labels`, `schemas/work-item-form`, `use-versioned-patch`, `use-work-item-cache`.
3. **Components:** `PanelTabs`, `ActivityFeed`, `WorkItemPicker`, `WorkItemEditPanel`, `NewWorkItemModal` + form, `SubItemProgress`, `SubItemsPanel`.
4. **Detail:** `WorkItemDetail`, `work-items/[workItemKey]/page.tsx` + `loading.tsx`, 1.7 list edits (stepper, page-segregation, parents).
5. **List:** `filter-defs`, `WorkItemsClient`, `work-items/page.tsx`, `loading`, `new/page.tsx`, `projects/[projectKey]/page.tsx`; the quick-view sheet.
6. **Board:** pdnd dependencies, `board-model` with property tests, the move route (if 2.2 lacks it), `use-work-item-move`, `use-board-dnd`, `use-board-keyboard`, columns, cards, lanes, `LayoutToggle`.
7. **Guards, e2e, docs.**

**Risks and traps:**

1. **Copying is not yet allowed in Islestone.** ADR 0001 is unsigned and `CLAUDE.md` forbids copies until it records the grant. Every file gets a `PROVENANCE.md` row (source path, commit, BUSL-1.1, changes); the pdnd packages are Apache-2.0 (allowlisted) and get `NOTICE` lines if required.
2. **One client cache.** ADR 0005 §3 requires one; the map assumes SWR. Choosing TanStack Query turns the data hooks, `use-entity-list-ids`, `user-combobox` (1.2) and every rendered test's `SWRConfig` wrapper into rewrites. Decide before step 1.
3. **Ownership ping-pong between the sibling maps.** 1.2 hands `aside-panel` to 1.7 and `user-combobox` to 1.4; 1.2 hands `use-tenant-swr`/`use-tenant-mutation` to 1.3/1.7 while 1.7 hands them to 2.2/2.3; 1.4 assumes 1.2 brings `AppIcon` while 1.2 calls it unaudited; 1.4 deletes `listAssignableUsers`, which the picker's route needs. This map takes all of them. If an earlier sub-phase lands any of them first, its row here becomes "already present, check the edit". The `hash-sync` manifest of 1.2 must list every MIXED file this map edits (`bulk-action-bar`, `aside-panel`, `user-combobox`, maybe `table-title-cell`) as an Islestone fork, or the drift check fails.
4. **The list is cursor-only now.** The source fetches up to 5,000 rows, sorts them in memory (`sortRowsByDisplay`) and reveals them with `useThresholdLoadMore`. At H2's 100,000 items that does not hold. Sorting must be server orders backed by indexes, and loading is cursor pages. Response shapes differ: the source paginated branch returns `{ items, pageInfo: { nextCursor, hasNextPage } }`, while 1.2's `useCursorPagination` expects `{ rows, nextCursor }` and is not SWR-backed (so not optimistic). Agree one envelope with 2.2, and use `swr/infinite` (or a thin per-page SWR key list) so optimistic updates and rollback reach every loaded page.
5. **Filter options derived from loaded rows break under pagination.** `assigneeOptionsFromTasks` and `controlOptionsFromTasks` build options from the rows on screen. With cursor pages, states, types, labels and projects come from server props (small sets), and assignee options from the members list.
6. **KPI strip semantics change.** `metrics.byStatus.OPEN` (TasksClient 552) has no meaning without the enum; use 2.2's `groupBy stateCategory`, and keep "overdue" computed in `NOTIFICATIONS_TZ` on the server so the card and the filter agree (2.2's KPI-consistency test).
7. **A board needs one team.** States belong to a team, and the workspace list spans teams. Show columns by state only for a project (one team) or a `teamId` filter; otherwise columns are the five categories, and a drop maps to the target team's default state of that category (2.2's bulk rule). Say so in the UI rather than mixing two teams' "In review" columns.
8. **Optimistic order.** The client may show its own `keyBetween` key; the server's key wins on response. Never compare keys with `localeCompare` (ADR 0002 §5; the column is `COLLATE "C"`). A move takes no `If-Match` because `sortKey` is not versioned, but a move that also changes state does increase the version; the cached row must take the returned version or the next text edit 409s.
9. **409 on autosave.** The source's autosave PATCH has no version. Islestone requires `If-Match` on title and description, so the panel must keep the version from each response and serialise writes per item (ADR 0005 §3), or two quick edits conflict with themselves.
10. **Strict TypeScript in Islestone.** `noUncheckedIndexedAccess` flags `cfg[card.id]`, label-map lookups and `TASK_TRANSITIONS[current]`-style reads; `@typescript-eslint/consistent-type-imports` with separate type imports; `no-console`; no explicit `any`.
11. **ADR 0006 vocabulary is enforced by lint (planned).** Every identifier, i18n key, testid, route segment and storage key above must use the Islestone words; "Board" is a layout label (`ViewLayout.BOARD`), never a model name; `CANCELLED` with two Ls; "Status" may appear only as the UI label of a workflow state.
12. **Route-dir imports.** `LinkedTasksPanel` and `CalendarClient` import `NewTaskModal` from a route directory, which the source guard allowlists. Moving the modal and form to `src/components/work-items/` removes the need; keep the route dir private.
13. **Hard-coded lists in other sub-phases.** `STEPPER_ENTITIES` + `ui.recordStepper.*` (`entity-prev-next-nav`), `MAIN_PAGES`/`SUBPAGES` (`page-segregation`), `PARENT_MAP` (`canonical-parents`), `SECTION_LABELS` (`BackAffordance`) and the i18n `workItems` namespace all need entries in the same PR, or the stepper names nothing and the back link points nowhere.
14. **`workItemPath()` is born in 2.2 and pointed by 2.3.** 2.2's notifications build links before the page exists. Add a test that the helper's path matches a real `page.tsx` under `src/app` so the two cannot drift.
15. **Date-only due dates.** `dueDate` is `@db.Date`; the server must serialise `YYYY-MM-DD` (not an ISO instant) or `parseYMD` and the overdue badge shift by a day west of UTC. `JSON.parse(JSON.stringify(...))` on the server page turns `Date` into an instant; serialise explicitly.
16. **Undo toast state is module-scoped.** Commits survive navigation (the detail delete navigates first and commits later). Tests must flush or `cancelPendingUndoToast` between cases, and SWR under fake timers needs the recipe in `2026-08-10-swr-under-fake-timers.md`.
17. **pdnd with virtualised columns.** Unmounted cards cannot be drop targets; make the column the fallback target with closest-edge on mounted cards, and use auto-scroll. Keyboard and screen-reader paths are not provided by pdnd and are an H2 gate; build them in this sub-phase, not later.
18. **Hydration.** `disabledDays={{ before: startOfUtcDay(new Date()) }}` (TasksClient 936) and any overdue badge compute the clock in render; keep them inside client-only effects or derive from a server-supplied "today", as the ported hydration guard requires.
19. **Bundle size and the client env guard.** Nothing in `src/components/work-items/**` may import `@/env`, Prisma, or server schemas; `workflow-state.ts`, `fractional-index.ts` and `work-item-key.ts` are client-reachable and must stay pure. Islestone's `client-env-boundary` guard walks this graph.
20. **Test harness gaps.** Islestone has no `@testing-library/user-event` and no integration Jest project yet; source rendered tests are testid-first and must be converted to role/label queries.
