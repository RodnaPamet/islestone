## Summary

## Prisma models and migrations

- **No models, enums, RLS policies, triggers or migrations are created in 2.3.** Islestone starts a fresh migration history; no source migration is relevant. RLS for every table read here is created with the table in 1.3/1.6/2.1/2.2.

  - `WorkItem`: `id`, `projectId`, `teamId`, `number`, `typeId`, `title`, `description` (encrypted), `stateId`, `stateCategory`, `priority`, `assigneeId`, `creatorId`, `parentId`, `sortKey`, `dueDate`, `version`, `deletedAt`, `deletedByUserId`. - **Indexes the views depend on** (ADR 0002 §13, created by 2.1): project manual order `[tenantId, projectId, sortKey, id]`; board columns `[tenantId, projectId, stateId, sortKey]`; sub-items `[tenantId, parentId, sortKey]`; recently changed `[tenantId, projectId, updatedAt, id]`; filter by type `[tenantId, typeId]`; labels `[tenantId, labelId, workItemId]`. **If 2.3 offers more list sorts** (due date, priority, title, assignee), each needs a keyset order in 2.2's pagination helper and a backing index, which is a migration and a Layer C entry in the ported index guardrail. Board order is the item's single `sortKey` (ADR 0002 §5); a per-view order would be a new table (ADR 0002 "What would change this decision").

**Risks and traps:**

1. **Copying is allowed** (ADR 0001 D1, Accepted 2026-11-18). Every file gets a `PROVENANCE.md` row (source path, commit, BUSL-1.1, changes); the pdnd packages are Apache-2.0 (allowlisted) and get `NOTICE` lines if required.
2. **One client cache.** ADR 0005 §3 requires one; the map assumes SWR. Choosing TanStack Query turns the data hooks, `use-entity-list-ids`, `user-combobox` (1.2) and every rendered test's `SWRConfig` wrapper into rewrites. Decide before step 1.
3. **Ownership ping-pong between the sibling maps.** 1.2 hands `aside-panel` to 1.7 and `user-combobox` to 1.4; 1.2 hands `use-tenant-swr`/`use-tenant-mutation` to 1.3/1.7 while 1.7 hands them to 2.2/2.3; 1.4 assumes 1.2 brings `AppIcon` while 1.2 calls it unaudited; 1.4 deletes `listAssignableUsers`, which the picker's route needs. This map takes all of them. If an earlier sub-phase lands any of them first, its row here becomes "already present, check the edit". The `hash-sync` manifest of 1.2 must list every MIXED file this map edits (`bulk-action-bar`, `aside-panel`, `user-combobox`, maybe `table-title-cell`) as an Islestone fork, or the drift check fails.
4. **The list is cursor-only now.** The source fetches up to 5,000 rows, sorts them in memory (`sortRowsByDisplay`) and reveals them with `useThresholdLoadMore`. At H2's 100,000 items that does not hold. Sorting must be server orders backed by indexes, and loading is cursor pages. Response shapes differ: the source paginated branch returns `{ items, pageInfo: { nextCursor, hasNextPage } }`, while 1.2's `useCursorPagination` expects `{ rows, nextCursor }` and is not SWR-backed (so not optimistic). Agree one envelope with 2.2, and use `swr/infinite` (or a thin per-page SWR key list) so optimistic updates and rollback reach every loaded page.
5. **Filter options derived from loaded rows break under pagination.** `assigneeOptionsFromTasks` and `controlOptionsFromTasks` build options from the rows on screen. With cursor pages, states, types, labels and projects come from server props (small sets), and assignee options from the members roster (`useTenantMembers`), so no facet is row-derived and `useRetainedFilterOptions` is not needed on this page.
6. **KPI strip semantics change.** `metrics.byStatus.OPEN` (TasksClient 552) has no meaning without the enum; use 2.2's `groupBy stateCategory`, and keep "overdue" computed in `NOTIFICATIONS_TZ` on the server so the card and the filter agree (2.2's KPI-consistency test).
7. **A board needs one team.** States belong to a team, and the workspace list spans teams. Show columns by state only for a project (one team) or a `teamId` filter; otherwise columns are the five categories, and a drop maps to the target team's default state of that category (2.2's bulk rule). Say so in the UI rather than mixing two teams' "In review" columns.
8. **Optimistic order.** The client may show its own `keyBetween` key; the server's key wins on response. Never compare keys with `localeCompare` (ADR 0002 §5; the column is `COLLATE "C"`). A move takes no `If-Match` because `sortKey` is not versioned, but a move that also changes state does increase the version; the cached row must take the returned version or the next text edit 409s.
9. **409 on autosave.** The source's autosave PATCH has no version. Islestone requires `If-Match` on title and description, so the panel must keep the version from each response and serialise writes per item (ADR 0005 §3), or two quick edits conflict with themselves.
10. **Strict TypeScript in Islestone.** `noUncheckedIndexedAccess` flags `cfg[card.id]`, label-map lookups and `TASK_TRANSITIONS[current]`-style reads; `@typescript-eslint/consistent-type-imports` with separate type imports; `no-console`; no explicit `any`.
11. **ADR 0006 vocabulary is enforced by lint (planned).** Every identifier, i18n key, testid, route segment and storage key above must use the Islestone words; "Board" is a layout label (`ViewLayout.BOARD`), never a model name; `CANCELLED` with two Ls; "Status" may appear only as the UI label of a workflow state.
12. **Route-dir imports.** `LinkedTasksPanel` and `CalendarClient` import `NewTaskModal` from a route directory, which the source guard allowlists. Moving the modal and form to `src/components/work-items/` removes the need; keep the route dir private.
13. **Hard-coded lists in other sub-phases.** `STEPPER_ENTITIES` + `ui.recordStepper.*` (`entity-prev-next-nav`), `MAIN_PAGES`/`SUBPAGES` (`page-segregation`), `PARENT_MAP` (`canonical-parents`), `SECTION_LABELS` (`BackAffordance`) and the i18n `workItems` namespace all need entries in the same PR, or the stepper names nothing and the back link points nowhere.
14. **`workItemPath()` is born in 2.2 and pointed by 2.3.** 2.2's notifications build links before the page exists. Add a test that the helper's path matches a real `page.tsx` under `src/app` so the two cannot drift.
15. **Date-only due dates.** `dueDate` is `@db.Date`; the server must serialise `YYYY-MM-DD` (not an ISO instant) or `parseYMD` and the overdue badge shift by a day west of UTC. `JSON.parse(JSON.stringify(...))` on the server page turns `Date` into an instant; serialise explicitly.
16. **Undo toast state is module-scoped.** Commits survive navigation (the detail delete navigates first and commits later). Tests must flush or `cancelPendingUndoToast` between cases, and SWR under fake timers needs the recipe in `2026-08-10-swr-under-fake-timers.md`.
17. **pdnd with virtualised columns.** Unmounted cards cannot be drop targets; make the column the fallback target with closest-edge on mounted cards, and use auto-scroll. Keyboard and screen-reader paths are not provided by pdnd and are an H2 gate; build them in this sub-phase, not later.
18. **Hydration.** `disabledDays={{ before: startOfUtcDay(new Date()) }}` (TasksClient 936) and any overdue badge compute the clock in render; keep them inside client-only effects or derive from a server-supplied "today", as the ported hydration guard requires.
19. **Bundle size and the client env guard.** Nothing in `src/components/work-items/**` may import `@/env`, Prisma, or server schemas; `workflow-state.ts`, `fractional-index.ts` and `work-item-key.ts` are client-reachable and must stay pure. Islestone's `client-env-boundary` guard walks this graph.
20. **Test harness gaps.** Islestone has no `@testing-library/user-event` and no integration Jest project yet; source rendered tests are testid-first and must be converted to role/label queries.
21. **Activity phrases silently degrade.** `PanelActivityFeed`'s `ENTITY_PREFIX` does not strip `WORK_ITEM_`, and an unmapped action falls back to the lower-cased code, so a missed edit produces "dana lee work item state changed" rather than an error. The ported `activity-humanize` test covers `humanizeDetail` only: add a case that every action 2.2 writes resolves to a phrase key.
22. **Comments are code here.** Several primitives that are otherwise copied unchanged carry compliance prose in comments (`kpi-filter-card`, `kpi-accent`, `mini-area-chart`, `table-title-cell`, `bulk-action-bar`, `aside-panel`, `list-backfill-cap`, the three data hooks). ADR 0006's "prose follows code" makes each a defect; the rows name the lines. Before review, sweep every copied file with `grep -niE 'task|control|risk|asset|evidence|vendor|polic|finding|audit|framework|SOC|NIS2'`.
23. **Guards that read fixed paths pass on nothing after a rename.** Every ported guard either derives its population from `gitFiles()` or cross-walks its curated list with it, and each proves itself on a planted fixture (Islestone `CLAUDE.md`, "Test conventions"). A guard copied with its source `readdirSync` walk or its fixed list of `tasks/` paths reads files that do not exist in Islestone.
24. **The roster shape is a contract between three files.** `listAssignableUsers` (1.4's file), the assignable route and `user-combobox` must agree on `{ id, name, email, image }`. 1.4's map deletes the function and this map re-adds it; whoever lands second must not narrow the shape.
