Islestone's `CLAUDE.md` still says "do not copy until ADR 0001 records the grant", so the porting PR has to cite the grant reference and add a `PROVENANCE.md` row for every file below. Line counts come from `wc -l` at the source commit.

## Summary

- **What moves (about 12.3k source lines).** The authenticated app shell:
  - the frame, chrome and sidebar primitives in `src/components/layout`;
  - the three page shells (`EntityListPage`, `EntityDetailLayout`, `DashboardLayout`) and their `ListPageShell` and `PageHeader`;
  - the ⌘K command palette, the `useKeyboardShortcut` registry and the `?` help overlay;
  - the tenant and org context providers, the theme provider, toggle and anti-FOUC constants;
  - next-intl request config and locale constants;
  - the back-affordance nav libs;
  - the tenant and `(app)` route-group layouts, the root `providers.tsx`, and the root error and not-found pages.
- **By action.** 33 files COPY verbatim (4,023 lines). 33 files COPY+EDIT (8,307 lines). 4 code files REWRITE with the source as a template (1,107 lines: `SidebarNav.tsx`, `use-palette-commands.ts`, `lib/search/types.ts`, `notification-href.ts`). About 8 files are fresh, with no source.
- **The catalogue.** `messages/en.json` is REWRITTEN as an extract. Keep about 450 of 14,981 leaf keys, in 11 namespaces. `bg.json` is not ported.
- **What is cut (2,665 lines skipped).**
  - The compliance nav register: `OrgSidebarNav`, the sidebar's nav sections and the palette's Controls/Risks/Policies/Evidence/Frameworks/Vendors/agent commands.
  - The calendar badge, the agent-inventory gate, the risk money formatter (`risk-coherence`) and the process-canvas module flag.
  - The onboarding tour (8.2), the assistant launcher (6.4), the billing plan read (8.1), SWR devtools and web-vitals (1.6).
  - The legacy compliance notification-link rewriter.
- **Navigation is written fresh.** My Work, Inbox, Views, Projects and Settings, following ADR 0006. The palette's navigation and actions are fresh too.
- **No Prisma models, no migration, no RLS policy in this sub-phase.** The shell only reads models that 1.3, 1.4 and 1.6 create.
- **New runtime dependencies:** `next-intl`, `cmdk`, `@radix-ui/react-dialog`, `@radix-ui/react-visually-hidden`, `lucide-react`, `sonner`, `swr` (1.2 may already add some of them).
- **Hard prerequisites:**
  - 1.2: `@inflect/ui`, the GENERIC `src/components/ui/*` files, tokens and the Tailwind theme.
  - 1.3 / 1.4: `auth()`, `getTenantServerContext`, `Role`, `PermissionSet`, `signOut`.
  - Stub interfaces are given below so 1.7 can run in parallel with them.

**Known traps**

- **`noUncheckedIndexedAccess`.** Islestone sets it and the source does not. A trial `tsc` run of the scope files under Islestone's flags reported possibly-undefined errors at:
  - `command-palette.tsx:267`;
  - `use-keyboard-shortcut.tsx:493-498`;
  - `entity-prev-next-nav.tsx:144,148,188,189`;
  - `canonical-parents.ts:366-367`;
  - `page-segregation.ts:413`;
  - and in 1.2 files: `toggle-group.tsx:229,231`, `filter/filter-list.tsx:126,149,154`, `packages/ui/.../use-in-viewport.tsx:49`.

  A byte-identical 1.2 copy cannot be fixed in place: 1.2 must either relax the flag for `packages/ui` through a separate tsconfig project, or upstream the fix. Imports that could not resolve in the trial (next-intl and others not installed) may have hidden more of these, so re-run `tsc` after `npm i`.
- **Lint differences.**
  - Islestone enforces `@typescript-eslint/consistent-type-imports` with `separate-type-imports`. Source files use inline `import { type X }` and value imports used only as types (for example `import { ReactNode } from 'react'` in `ListPageShell.tsx`, and `import { type BreadcrumbItem }` in `EntityDetailLayout.tsx` and `EntityListPage.tsx`). Run `eslint --fix`; the client-env guard's import graph depends on those being `import type`.
  - `no-console` is an error, which catches the two `error.tsx` files.
  - The keyboard hook (line 451) and `ClientProviders` read raw `process.env`, against Islestone's env-module rule.
- **The client-reference-proxy trap.** `theme-constants.ts` and `locale-constants.ts` must never gain `'use client'`. The root layout imports their string values on the server, and a client module would hand it a proxy, which silently breaks the theme cookie read (documented at the top of `theme-constants.ts`).
- **The next-intl plugin disables Next's webpack build worker.** It injects a `webpack` hook, which turns `webpackBuildWorker` off. The source sets `experimental.webpackBuildWorker: true` explicitly after measuring OOMs (`next.config.js` lines 170-200); do the same.
- **next-intl in Jest.** The package is ESM-only. `__mocks__/next-intl.js` must sit at the repo root beside `node_modules`, and it requires `../messages/en.json`. Tests that render server components need `next-intl/server` mocked per test.
- **The provider order is load-bearing.** `NextIntlClientProvider` must wrap `<Providers>`; otherwise the palette, help overlay and toasts throw during SSR and every route returns 500 (comment in the source root layout). Within `Providers`, `KeyboardShortcutProvider` must sit outside `CommandPaletteProvider`, because the palette registers `mod+k`.
- **`TenantProvider` throws without a tenant.** `useTenantContext()` throws outside it. That is why 6.4's launcher mounts in `(app)/layout.tsx` and not in `AppShell`, and why an org shell (8.3) must not mount tenant-only chrome.
- **Hard-coded lists to rewrite together.** `MAIN_PAGES`/`SUBPAGES` (`page-segregation.ts`), `PARENT_MAP` (`canonical-parents.ts`), `SECTION_LABELS` (`BackAffordance.tsx`), `common.sections.*`, `STEPPER_ENTITIES` + `ui.recordStepper.*`, `SearchHitType` + `SEARCH_TYPE_DEFAULTS` + `commandPalette.entity*`, `nav-config.ts` + the palette navigation rows, and the `roles` catalogue against the `Role` enum. A route added later must touch `nav-config.ts`, `page-segregation.ts` and, for subpages, `canonical-parents.ts`; the page-segregation guard enforces the second.
- **Storage keys change.** With `UI_STORAGE_PREFIX = 'islestone'`, the theme cookie is `islestone_theme`, the locale cookie `islestone_locale`, and the sidebar and recents keys move. `THEME_INIT_SCRIPT` embeds the names at build time, so nothing else needs updating, but e2e specs that set cookies by name must change.
- **ADR 0006 words.** `Tenant*` identifiers are fine under option W1, but if the owner picks W2 the switcher and providers rename to `Workspace*` in the same change. The UI catalogue must not say "tenant", "Dashboard" (for My Work), "Board" or "Task"; that is why `common.ui.currentTenant`, `nav.dashboard`, `*.goToDashboard` and `nav.tasks` are dropped or renamed. The Settings path (`/settings` vs `/admin`) must agree with 1.4's middleware admin gate, which in the source protects `/t/:slug/admin/**` only.
- **Search is inert until 2.7.** Without the `ENTITY_SEARCH_AVAILABLE` gate, the palette would call `/api/t/:slug/search`, get a 404 and show "Search failed" on every keystroke.
- **The hash-sync interaction with 1.2.** TopChrome, `ui-storage` and `use-keyboard-shortcut` are classified GENERIC but are edited here. If 1.2's drift script expects byte equality for every GENERIC file, list these three (and every MIXED file 1.7 copies) as forked, or the drift report fails permanently.
- **No circular imports found.** `TopChrome` ↔ `AppShell` is type-only (`AppShellVariant`). `SidebarNav` → `command-palette-provider` is a one-way value import. Keep `nav-config.ts` free of component imports so the palette's navigation rows can share its href list without a cycle.
