## Summary

- **What moves (63 files, 12,282 source lines owned by 1.7).** The authenticated app shell:
  - the frame, chrome and sidebar primitives in `src/components/layout`;
  - the three page shells (`EntityListPage`, `EntityDetailLayout`, `DashboardLayout`) with `ListPageShell`, `PageHeader` and `FilterToolbar`;
  - the ⌘K command palette and the shortcut help overlay (opened with `mod+/`, that is Ctrl+/ or ⌘/);
  - the tenant and org context providers, the theme provider, toggle and anti-FOUC constants;
  - next-intl request config and locale constants;
  - the back-affordance nav libs;
  - the tenant and `(app)` route-group layouts, the root `providers.tsx`, and the root error and not-found pages.
- **By action.** 16 files COPY verbatim (1,707 lines). 43 files COPY+EDIT (9,468 lines; 14 of them are comment-only edits). 4 code files REWRITE with the source as a template (1,107 lines: `SidebarNav.tsx`, `use-palette-commands.ts`, `lib/search/types.ts`, `notification-href.ts`). 7 files are fresh, with no source (section J), plus the `PROVENANCE.md` rows.
- **Owned by an earlier sub-phase, verified present here (7 files, 1,155 lines).** `use-keyboard-shortcut.tsx`, `keyboard-shortcut-internals.ts`, `use-dropped-link-click-guard.ts`, `ui-storage.ts` and `__mocks__/next-intl.js` are 1.2's; `auth/session-expiry.ts` is 1.4's; `notifications/mark-read.ts` is 1.6's. 1.7 does not copy them and does not count them.
- **The catalogue.** `messages/en.json` is built **key by key**, the rule 1.2 set for `common.ui` and `common.chart` (1.2 map §6.6). 1.7 adds about 114 leaves on top of 1.2's extract, out of 14,981 in the source. `bg.json` is not ported.
- **What is cut (2,665 lines in section K, the 16-line `/dashboard` shim and the two root icon files).** Separately, section M routes 8 files (1,738 lines) that sibling maps handed to 1.7 to the sub-phases that actually use them.
  - The compliance nav register: `OrgSidebarNav`, the sidebar's nav sections and the palette's Controls/Risks/Policies/Evidence/Frameworks/Vendors/agent commands.
  - The calendar badge, the agent-inventory gate, the risk money formatter (`risk-coherence`) and the process-canvas module flag.
  - The onboarding tour (8.2), the assistant launcher (6.4), the billing plan read (8.1), SWR devtools and web-vitals (1.6).
  - The legacy compliance notification-link rewriter, the bell's flat `/api/notifications` fallback, and the legacy `/dashboard` redirect shim.
- **Navigation is written fresh.** My Work, Inbox, Views, Projects and Settings, following ADR 0006. The palette's navigation and actions are fresh too.
- **No Prisma models, no migration, no RLS policy in this sub-phase.** The shell only reads models that 1.3, 1.4 and 1.6 create.
- **New runtime dependencies:** `next-intl`, `cmdk`, `@radix-ui/react-dialog`, `@radix-ui/react-visually-hidden`, `lucide-react`, `sonner`, `swr` (1.2 adds several of them first).
- **Hard prerequisites:**
  - 1.2: `@inflect/ui`, the GENERIC `src/components/ui/*` files, **and 1.2's exceptions**: the 14 MIXED files it copies (among them `table/data-table.tsx`, `table/selection-toolbar.tsx`, `filter/filter-list.tsx`, `filter/filter-select.tsx`, `filter/filter-select-utils.ts`, `filter/use-filter-presets.ts`), `src/lib/filters/filter-presets.ts`, `src/lib/text-utils.ts` and the Islestone-owned `icons/index.tsx` stub. Also tokens and the Tailwind theme.
  - 1.3 / 1.4: `auth()`, `getTenantServerContext`, `Role`, `PermissionSet`, `signOut`.
  - 1.6: the workspace notification routes.
  - Stub interfaces are given below so 1.7 can run in parallel with them.

## Prisma models and migrations

- **No models, enums, RLS policies, triggers or migrations are created in 1.7.** Islestone starts a fresh migration history; nothing from `prisma/migrations/` is relevant here.
- Models the shell **reads** (through other sub-phases' code), with the compliance parts to drop:
  - `Tenant` (1.3): `id`, `slug`, `name`. Do NOT carry `currencySymbol`, which the source threads through the tenant context for risk money.
  - `TenantMembership` (1.3): `role`, `status`; `customRoleId` if 1.4 ports custom roles. The resolver lives in 1.3/1.4 and must run under 1.3's RLS / global-client rules.
  - `Organization`, `OrgMembership` (1.3): read only through the JWT `orgMemberships` claim (1.4).
  - `Notification` (1.6): the bell expects `{ id, type, title, message, read, linkUrl, createdAt }`.
- Reads that must NOT come with this port: `TenantSecuritySettings.processCanvasEnabled` (the module flag in `tenant-context.server.ts`) and `BillingAccount.plan` (`entitlements-server.ts`).
- `Role` and `OrgRole` enums come from 1.3/1.4 (Islestone roles OWNER / ADMIN / MEMBER-or-EDITOR / GUEST / VIEWER, ADR 0006 option M). The `roles` catalogue namespace must list exactly that enum, because the switchers and the sidebar read it with a computed key. `tests/unit/i18n/enum-labels-cover-every-value.test.ts` in the source is the pattern for a guard.
- The two-tenant behaviour this sub-phase owns is the layout gate: a slug the user has no membership for renders 404 (`notFound()`), not another workspace's shell. Prove it in an integration or e2e test once 1.3/1.4 exist (H1).
