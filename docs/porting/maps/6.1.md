## Summary

- **What moves.** The engine mechanism under `src/lib/agentic`: the static driver (705 lines) and the Tool Runner driver (12 files, 4,180 lines), the engine-neutral tool core (`engine-tools/`), the run store, step recorder, run settlement and deferral store (`drivers/`), run caps, turn caps, monthly token budget, run concurrency cap, the kill switch at three scopes, the behavioural circuit breaker, policy cards and the autonomy ceiling, agent profiles (run-time half), the skill loader with its text scan, mount gate and evaluation-record checker (lifted out of `flue/skills/`), the run-definition registry mechanism, driver selection and the per-tenant engine switch, context sealing, content provenance and the external-AI transfer gate. Also `src/app-layer/ai/guard/**` (injection and egress guard), the AI decision log, the run lifecycle usecase (`workflow-runs.ts`, trimmed), two jobs (run execute, run reaper), the driver conformance suite and four ESLint rules (`anthropic-client-single-seam`, `require-agent-attribution`, `no-typed-run-driver-read`, `no-raw-prompt-logging`).
- **What is cut or deferred.** Cut: Flue (48 files under `flue/`, 10,046 lines, plus `@flue/runtime`, `@earendil-works/pi-ai` and `valibot`), openshell (10 files), all 10 compliance workflows, the harness scanner, recertification, audit procedures and workpapers, SAP, third-party app scans, service-principal disable, owner-orphan pass, credential hygiene, the integration passport, evidence artefacts, the behaviour fingerprint and the agent risk questionnaire. Deferred: A2A (17 files) and the proposal, MCP and delegate modules that 6.2 to 6.4 own. In all, 152 of the 234 files in `src/lib/agentic` (34,289 lines) are not in the manifest, and 6 manifest rows are SKIP.
- **What is renamed** (ADR 0006 rule 8). `WorkflowRun` → `AgentRun`, `WorkflowStep` → `AgentRunStep`, `WorkflowRunDeferral` → `AgentRunDeferral`, `RegisteredAgent` → `Agent`, `TenantSkill`/`TenantSkillVersion` → `Skill`/`SkillVersion`, `WorkflowDefinition` → `RunDefinition`. "Workflow" leaves the engine entirely. The full table is under "Conventions".
- **What is stubbed.** The MCP tool funnel (`runReadTool`, `runProposeTool`, the invocation builder) belongs to 6.2. 6.1 adds one seam, `src/lib/agentic/funnel.ts`, with the same signatures and an empty tool registry. 6.2 replaces its bodies with the real `src/lib/mcp` code without touching an engine file.
- **Pulled forward from later sub-phases**, because the engine does not compile or run without them: the AI decision log (6.6), a minimal `Agent` model (6.3) and five leaf MCP modules (6.2).
- **Size.** About 31,900 source lines are read, and about 27,000 land in `src/` after the cuts, plus about 350 new lines (the funnel seam and two extracted helpers). Add 1,934 lines of ESLint rules and 955 lines of test helpers. Of the 151 source test files reviewed (47,390 lines), 109 come over as COPY or COPY+EDIT (about 29,800 lines), 31 move to later sub-phases and 11 are SKIP.
- **Database.** 14 of the 56 `agentic.prisma` models are KEEP, 22 are LATER and 20 are LEAVE BEHIND. `AiDecisionLog` comes from `automation.prisma`. Islestone writes one fresh migration; the RLS policies, triggers and CHECKs come from the source migrations named in the Prisma section.
- **Gate before any copy.** ADR 0001 must record the BUSL grant. `PROVENANCE.md` still says "pattern only" for every inflect-compliance row. ADR 0006 needs amendment rows for "Run definition", "Agent profile", "AI guard" and "Decision log", which have no row today.

## Prisma models and migrations

Islestone starts with a fresh migration history, so no source migration is replayed. Write **one migration** (for example `<ts>_agent_engine`) after 1.3's base migration and 1.5's audit and encryption migrations. Put the models in a new `prisma/schema/agent.prisma` and the enums in Islestone's `enums.prisma` (one file per rule, as 1.3 sets it up). Replaying is the wrong tool because the source history is about 30 incremental ALTERs, backfills and `NOT VALID` rewrites (for example `20260913000000_tenant_fks_composite_batch2`). Their rolling-deploy hedges have no meaning on an empty database: nullable columns "because added to a populated table", and text columns plus CHECK where an enum would do.

### Known traps

- **The funnel is the engine's authority.** Until 6.2 lands, `funnel.ts` has an empty registry. Every Tool Runner run settles `EMPTY_CATALOGUE`, and a static definition with a READ or PROPOSE step fails at its first tool call. That is the safe direction, but it means 6.1 delivers no usable agent run in production. The static driver relies on the funnel for its tool-boundary kill-switch and guard checks; the Tool Runner checks the kill switch itself before every model call. Recommend landing 6.2's funnel core (`authorize.ts`, registry, invocation builder) immediately after 6.1, or folding it into 6.1.
- **"Make both drivers pass it."** The source has no conformance adapter for the static driver: it takes no model turns, so the run scenarios do not apply to it. Only the Tool Runner (run half, `tests/unit/agentic/tool-runner-driver.test.ts`) and Flue (`tests/flue/…`, cut) have adapters. Islestone either writes a static adapter that declares a variance for each model-turn scenario, each naming an owner decision (`checkVariances` refuses one without), or records in an ADR that the run half binds reasoning engines only. Both engines can pass the admission half. Recommend the ADR note.
- **`Agent` before 6.3.** Runs, cards, kills, breakers and profiles all FK the agent, and the admission scenario reads its standing. So 6.1 lands a minimal `Agent`, and 6.3 extends it (delegate, sessions, checkout, budgets, transfer, retirement triggers). The alternative is plain `agentId` strings with no FK until 6.3. The owner should pick one before the migration.
- **Hard-coded paths and lists.**
  - `SKILLS_DIR` is `process.cwd()`-relative (`skills/index.ts` L132), so tests must run from the repository root.
  - `MCP_TOOL_CORPUS`, `MCP_READ_TOOL_NAMES`/`MCP_PROPOSE_TOOL_NAMES` and the `tool-data-scope` table are emptied in 6.1 and must be refilled in 6.2. `content-provenance` fails closed on any tool missing from the corpus, so a 6.2 tool left out of it is untrusted, not silently trusted.
  - `AGENT_ATTRIBUTED_MODELS` and `RUN_MODEL` in the ESLint rules name Prisma delegates as strings. A rename that misses them disables the rule without an error. `require-agent-attribution`'s own guard catches an empty population.
- **Encrypted write-once columns.** `AgentProfileVersion.instructions`, `SkillVersion.instructions` and `AgentRunDeferral.transcriptJson` are frozen by triggers but rewritten by 1.5's DEK and KEK rotation sweeps. Port each trigger's re-wrap exception exactly. The resolver's recompute of `instructionsHash` and `approvedContentHash` is the real freeze for an encrypted column. Do not drop it as redundant.
- **The decision log's encryption claim.** The source's `decision-log/index.ts` L35 says the output summary "is encrypted at rest either way", but `encrypted-fields.ts` at this commit has no `AiDecisionLog` entry. Decide in 6.1: add `AiDecisionLog: ['outputSummary']` (recommended, because the summary is model output about workspace content), or fix the comment.
- **`AgentDriverMode` is an enum read as text.** Keep `agent-driver-stored-mode.ts` and `no-typed-run-driver-read` even though Islestone starts fresh. The rollback hazard (an image that knows fewer engines than the data) is a property of enums, not of history.
- **Literal "Inflect" strings reach the model.** The preamble, the compaction instruction, `<run_state source="inflect">` and the provider ids. `tool-runner-locked-params.test.ts` pins the text, so update both together, and grep the copied files for `inflect` (case-insensitive) before merging. The kept source files carry 39 such lines across 19 files, most of them prose.
- **Hash domain strings.** `inflect-agent-profile-content/1` and `/2` and `inflect-tool-runner-deferral/1` become `islestone-*`. They can change now because no stored hash exists. After the first approved version they are one-way.
- **`canonical-json` is not inflect-compliance code.** It is BUSL-1.1 scanent, outside the grant. Rewrite it and test that `mount-gate`'s set comparison and `resolve.ts`'s `skillPinDrift` behave identically.
- **The monthly budget versus ADR 0003 §11.** The source's tenant-level budget treats "null" as unlimited and checks once before a run. ADR 0003 asks for a finite per-agent `AgentBudget` with reservation (6.3). Port the source mechanism now and say in its header that 6.3 replaces the unlimited default.
- **Metrics names.** The record helpers move into Islestone's `metrics.ts` with `islestone.*` meter names. Dashboards and alerts written against the source names do not carry over.
- **`@swc/jest` versus ts-jest.** The source suite runs on ts-jest. Copied tests that rely on `jest.mock` hoisting past type-only imports, or on `@ts-nocheck` and file-level `any`, need checking under SWC. Islestone's `tsconfig.json` sets `noUncheckedIndexedAccess: true` and the source does not, so expect `tsc` errors wherever the copied engine indexes arrays and records (`circuit-breaker.ts`, `tool-runner/execute.ts`, the policy stores). Fix them in the copy; do not relax the flag.
- **`ANTHROPIC_CUSTOM_HEADERS` must stay in `env.ts`.** Removing it as unused would let the SDK read it from `process.env` with no refusal.
- **Do not reintroduce Flue words through `Record<AgentDriver, …>` maps.** Each is exhaustive, so deleting `'flue'` from `AGENT_DRIVERS` makes `tsc` list every map to fix: `DRIVER_IMPLEMENTED`, `REASONING_ENGINE`, `RECORDED_MODE`, `RUNS_PROFILES`, `RUNS_FLOWS`, `RUNS_SUBAGENTS`, `RUNS_DEFERRALS` and `DRIVERS`. Use that list as the checklist.
