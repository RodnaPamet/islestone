## Summary

- **What moves.** The MCP funnel: `buildMcpInvocation` (principal ∧ credential, resolved once per request), `authorizeToolCall` (kill switch → audience → credential liveness → breaker → tool-manifest pin → deny-by-default exposure → autonomy ceiling → policy card → capability → resource scope → `assertPermission` → `assertCan*`, one `AUTHZ_DENIED` row per refusal), the read and propose registries with their loadable-set snapshot, per-domain redaction, the RFC 8693 token exchange (`POST /api/mcp/token`, signed audience-scoped tokens), the two-budget rate limit (`MCP_IP_CEILING_LIMIT` 600/min/IP before auth, `MCP_PER_KEY_LIMIT` 60/min per verified key after it, charged before the invocation is built), tool-definition pinning (`McpToolManifestPin`), deny-by-default tool grants (`AgentToolGrant`) and `local/require-mcp-tool-authorization`. The proposal queue: `createProposal` (schema-validate → sanitise → output guard → QUARANTINED or PENDING), approve / approve-with-edits / reject / bulk reject with four-eyes tiering, write-once `requiredApprovals`, the base-digest stale check, expiry, the deferral hook that resumes a parked run, retrospective sampling and review-quality metrics, the review page and quarantine view.
- **Every tool module is compliance except the mechanism.** 15 read tools and 5 propose tools ship in the source; none is kept as is. `list_tasks` and `get_tenant_context` are the generic-shaped ones and both are rewritten against 2.1/2.2 usecases. Islestone writes 7–13 read tools and 4–6 propose tools (projects, work items, comments, cycles, search, docs, analytics; work-item create/update, comment, relation, plan, schedule change), each when the sub-phase owning its usecase has landed.
- **What is cut.** The Entra grant and service-principal endpoints (642 lines), the outbound MCP clients and connector OAuth (`lib/mcp/client/**`, `wire-transport.ts`, `tools/external-tools.ts`, `integrations/mcp/**`, `mcp-server-provider.ts`: ≈4,000 lines, section J), pipelock receipts, the harness, recertification, audit-workpaper, framework, risk, control, evidence, finding and knowledge tools, the compliance resources, dashboard redaction rules, workpaper-dissent rules, the AUDITOR oversight switches, the external-write and process-map proposal kinds, and `/agents/compose`.
- **The source does not use the MCP SDK.** `protocol.ts` hand-rolls JSON-RPC for `2025-06-18` and `2024-11-05` and accepts batches. The 2026-07-28 revision (per-request `_meta` envelope, `server/discover`, SEP-2243 `Mcp-Method`/`Mcp-Name` headers, no `ping`, no batches, `resultType`, cache hints, in-band `input_required`) is served by `createMcpHandler` from `@modelcontextprotocol/server@2.4.0` (Apache-2.0) over a per-request low-level `Server`. Auth, budget and funnel stay in front of it. The SDK's legacy leg answers 406 unless `Accept` lists both `application/json` and `text/event-stream`, and it does not bound a body passed as `parsedBody`, so the route bounds it.
- **Ordering traps.** (1) MCP authenticates only with `TenantApiKey`, which 1.4 deferred to 5.2, and Phase 6 does not depend on Phase 5 (the first release is 0–2 + 6.1–6.4 + 7.1), so the API-key slice is pulled forward. (2) 6.1 recommends hard-coding registration enforcement, so `/api/mcp` admits only keys bound to an ACTIVE `Agent`; agents are created through 6.3's register, so the endpoint ships dark (`MCP_SERVER_ENABLED`) until 6.3. (3) `tools/propose-tools.ts` imports the proposals usecase, so everything that imports `tool-definitions.ts` lands with the queue (6.2b), not with the funnel library (6.2a).
- **Database.** Five tenant tables in fresh migrations (`AgentToolGrant`, `McpToolManifestPin` in 6.2a; `Proposal`, `ProposalApproval` in 6.2b; `ProposalSampleAudit` in 6.2d) with RLS, CHECKs and six trigger functions rewritten from eleven source migrations; `maxAutonomyLevel`, `requiresTokenExchange` and `agentId` on `TenantApiKey`; two `NotificationType` values. `AgentProposal` → `Proposal`, `SuggestionItemStatus` → `ProposalStatus`, `RegisteredAgentTool` → `AgentToolGrant`, `kind` becomes checked text (ADR 0003 §8, ADR 0006 rule 8).
- **Size.** About 17,800 source lines are read for the manifest; about 12,000 land after cuts (≈4,700 `lib/mcp`, ≈2,400 `lib/agentic`, ≈3,400 usecases and jobs, ≈2,800 UI and routes), plus ≈900 new lines (PM tools, the SDK adapter, schemas). About 75 test files (≈22,000 lines) come with it, most COPY+EDIT with PM fixtures.

- **Enforcement makes the endpoint dark until 6.3.** With registration enforced (6.1's recommendation, and the source's default for an absent settings row), `/api/mcp` refuses every key not bound to an ACTIVE `Agent`. Agents and bindings are created by 6.3. Ship behind `MCP_SERVER_ENABLED` and prove 6.2 with seeded agents in tests.
