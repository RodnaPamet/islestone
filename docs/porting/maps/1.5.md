Source commit: 5528464fc54a8681956f3b9ce23ca9c075f0420e

Destination paths are relative to `/home/user/islestone`. "1.3", "1.4", "1.6" and so on name the Islestone sub-phase that owns something removed here. Line numbers refer to the source file at the commit above. A bare test basename resolves under the directory given in its table's heading.

## Summary

- **What moves.** About 13,300 source lines are read, plus the 380-line audit extension that 1.3 cut from `prisma.ts` and a 520-line metrics subset. About 13,100 land: 10,800 in 1.5a and 2,300 in 1.5b (the rotation jobs plus their job-type, executor, schedule and route-permission wiring). About 82 test files (about 23,000 lines, most copied with edits) come with them. Field encryption: `encryption.ts`, the manifest, the Prisma encryption extension, the PII (email hash) extension, per-tenant DEKs (`tenant-keys.ts`, `tenant-key-manager.ts`), and later the two rotation jobs. The hash-chained audit trail: `src/lib/audit/**`, `logEvent`, the Prisma audit extension that 1.3 removed from `prisma.ts`, the outbox fallback and the org trail. Audit streaming (`audit-stream.ts`, `webhook-headers.ts`, the HMAC helper). The three rate-limit tiers: the in-process mutation tier inside `withApiErrorHandling`, and the edge read and auth tiers. Sanitisation (`sanitize.ts`, `safe-url.ts`). `safeFetch` with the self-hosted CIDR allowlist. Secret detection (`detect-secrets.sh`, `.secret-patterns`, the pre-commit hook, the CI guard). The production startup checks and their env-schema refusals.
- **What is cut.** All 56 compliance entries of the 57-model manifest. MCP and agent rate-limit presets. `sanitizePolicyContent`. Provider signature headers. The deprecated `logAudit`. The activity-feed and audit-log-viewer helpers (2.2, 8.3). The compliance halves of `instrumentation.ts` (telemetry, Sentry, mailer, automation, integrations: 1.6/5.x). The API-key liveness re-check in KEK rotation (5.2). Every compliance write-site test.
- **What is replaced.** Two modules are re-exports of the BUSL-1.1 `@rodnapamet/scanent-contract` package, and their code is not in this repository: `src/lib/audit-redact.ts` and `src/lib/security/cidr.ts`. Islestone writes both fresh against the tests that pin their contracts (or recovers the pre-2026-11-13 in-repo versions; see Ordering, step 3). Every `inflect` literal becomes `islestone`: HKDF salt and info strings, the subkey naming convention, dev fallback key, sentinel, `X-Inflect-*` headers, User-Agent, meter and tracer names.
- **Paths are kept.** `safeFetch` stays at `src/app-layer/automation/webhook-safety.ts` and the HMAC helper at `src/app-layer/integrations/webhook-crypto.ts`, the source paths. The 1.4 map (`oidc-client.ts`, COPY) and the 5.1 map (`action-executor.ts`) already import them there, and the guards read those literal paths. Relocating would add an edit to 16 downstream source files (listed under Import closure) and two tests.
- **The manifest is empty of business content.** It keeps one platform entry, `TenantSecuritySettings.auditStreamSecretEncrypted`, because the audit stream needs its HMAC secret encrypted. Sub-phases 2.2, 5.1 and 6.x add their own entries.
- **`User.emailHash` follows the source shape:** `String? @unique` in the schema, `NOT NULL` in the database, filled by the PII extension. The GAP-21 guard that pins that split comes with it (Prisma section).
- **Split recommended.** 1.5a (core) lands BEFORE 1.4, because 1.4's `requirePermission`, credentials and MFA code import the audit writer, the rate limiter and encryption. 1.5b (DEK rotation, KEK rotation and the outbox drain) lands after 1.6 provides `enqueue`/`runJob` and the job registry, and after 1.4 provides `requirePermission` and `route-permissions.ts`.
- **Gate before any copy.** None remains: ADR 0001 is Accepted (owner decisions, 2026-11-18), and its D1 allows copying from inflect-compliance. Every copied file gets a `PROVENANCE.md` row (see Ordering, step 0).

### Traps

- **One-way literals.** HKDF `info` strings, the salt, `HASH_FIELDS`/canonical JSON and the `v1:`/`v2:` prefixes become permanent with the first production ciphertext or audit row. Rename the `inflect-*` derivation strings in this PR or never. The dev fallback key and the sentinel may change later (the env test hard-codes the fallback, so change both together).
- **Set `LOOKUP_HASH_KEY` and `DERIVED_SUBKEY_KEY` at first deploy** (1.8), to their own values or to the KEK's. Otherwise the first KEK rotation needs the "set them to the outgoing key first" runbook step, and the startup check refuses a boot with `DATA_ENCRYPTION_KEY_PREVIOUS` set and those unset.
- **Upstash is a hosted sub-processor.** `RATE_LIMIT_MODE` defaults to `'upstash'` in the source schema. Without `UPSTASH_*` the limiters fail open to memory, per process and per edge isolate. Islestone's stack has plain Redis, which the REST client cannot reach. The owner chooses (open decision 5, hosting): Upstash (record it in the sub-processor list), a self-hosted serverless-redis-http proxy over the stack's Redis, or memory only. Default the schema to `'memory'` until then, so the behaviour is stated rather than an accident.
- **`getClientIp` trusts the first `x-forwarded-for` hop.** That is correct only behind a proxy that overwrites the header (1.8's edge). Otherwise a client chooses its own bucket.
- **Raw `process.env`.** The source reads it in `encryption.ts`, `egress-allowlist.ts`, `billing-mode.ts`, `rate-limit-middleware.ts`, `apiReadRateLimit.ts`, `edge-logger.ts`, `instrumentation.ts` and inside `Redis.fromEnv()`. Islestone forbids it outside the env modules. Every read moves to `@/env`. The Jest mock reads live, so tests that flip keys keep working; production values are snapshot at boot, which is what the code assumes. Rewrite the comments that argue for the raw read (`rate-limit-middleware.ts` L367–370).
- **Lint and type differences, source and tests.** Islestone has `no-require-imports` (the `require` in `prisma.ts` L348, the lazy one in `tests/helpers/db.ts`, and the test sites in the mechanical-fix table), `consistent-type-imports` (`PrismaClient`, `OrgAuditAction`, `PrismaTx`, `RequestContext`, `RateLimitConfig`, `NextRequest` value imports), `no-explicit-any` (`events/audit.ts` L14 and the test sites), `no-console` (`edge-logger.ts`, `instrumentation.ts`: per-file exceptions with reasons) and `noUncheckedIndexedAccess` over `src/` and `tests/` alike. Do not add a fake model to the real manifest for test convenience. The PII field map cannot be mocked the same way (module-private), so its `mapped: false` cases wait for 1.4.
- **`emailHash` is nullable in the schema and NOT NULL in the database, on purpose.** A future "tidy-up" that drops the `?` makes every create site name the hash; one that drops the SQL `NOT NULL` lets a row skip the hash and break lookups. `pii-hash-not-null.test.ts` fails on either. A raw client (no PII extension) must pass `emailHash` itself.
- **Immutability versus deletion.**

  - `AuditLog.userId ON DELETE SET NULL` passes the pseudonymisation shape but breaks hash verification for that row, unless the deletion also writes an `ERASURE_EXECUTED` record (8.3 must).
  - TRUNCATE bypasses the row trigger. `app_user` holds no TRUNCATE privilege; keep it that way.
- **`appendAuditEntry` runs on the global client in its own transaction** (advisory lock `hashtext(tenantId)`), outside the caller's transaction, by design.
